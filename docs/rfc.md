# 架构与协议约束

## 模块边界

- identity：生成与验证本机身份、原子保存配对配置、生成本机能力声明。
- scp / ukey2：首次本地密钥协商与手机授权。
- server：接收首次配对时手机反向发起的 OAFP 控制连接。
- client：OAFP 双向挑战、服务发现与文件 JSON API。
- media：验证临时 CA 和客户端证书，HTTPS Range 下载原始音频。
- sync：路径约束、内容哈希、manifest 与原子检查点。
- cli：参数、单实例锁、轮询与重试。

## 必须保持的机制

首次配对采用 UKEY2，本机设备 ID、P-256 和业务 RSA 密钥均本地生成，不借用其他电脑账号。手机返回 accept 后，只复用手机反向发起的默认控制连接；另建第二条默认连接曾导致手机提示失败。

能力声明中 DynamicConnection(tag 13) 为 0，只承诺已经实现的消息通道，不宣告未实现的动态流服务。业务层解密密钥根据 OAFP 连接方向选择。

日常同步只使用本设备已获手机授权的 KSC，直接建立文件会话，不重新发起首次手机确认。不能将临时加密会话建立或文件接口返回成功单独当作手机完整配对 UI 成功。

媒体服务通过认证后的 video.request 返回端口、CA 和临时客户端凭据。请求固定发送给已经认证的手机地址，校验 CA 并完成双向 TLS。凭据仅临时保存，函数结束后删除。

Range 从手机实际响应继续，首段和后续段长度不同。起点、总大小、实际长度必须一致；临时文件完整后才进入输出目录。同名异内容停止该轮，不覆盖。

## 兼容策略

公开项目只维护独立身份与媒体下载。旧账号、ADB、WebSocket/ZIP 实验保存在原研究目录，不打包为可用功能。根目录两个 Python 脚本只转发到包，支持原有命令书写方式。
